布局按项目选择，同仓可以混用；聚合模式不引入 minds/ 中间层，也不增加 .mind/ 配置目录。Markdown 与 HTML 是同一 output 的格式，不是两份独立源稿。

生命周期与引用

mind／output 创建、定位、改名、移动、删除。默认维护受管引用，有入站引用时拒绝删除。转换提供 dry-run、冲突拒绝与恢复。

additional 扩展资源

支持动态识别、展示、具体文件／目录重命名与删除。核心路径优先；扩展资源不自动进入构建、发布、RAG 或执行。

HTML 与 Mermaid

mf build 支持极简 HTML 和项目模板覆盖，渲染表格、代码、本地图片与 Mermaid。加载／语法失败保留可读源码和错误提示。

更可靠的发布定位

F16 修复保留并重新回归。创建、构建、本地发布、publish update 使用一致的内容定位，覆盖目录分块正文。

CLI 接管确定性操作

布局定位、资源生命周期、索引与绑定检查、迁移恢复由 CLI 处理；结构化输出和明确失败便于 Skill 调用与判定。

Skill 保留写作判断

mf-plan／mf-write 与 mf-cli 指引同步新模型，覆盖短文、多 output、旧稿增材、部分完成、明确延期和已有授权下继续执行。

03 / COMMAND CHANGES

命令怎么变：从 article 转向 mind 与 output

以下对照基于改动前 23b047c 的 CLI 手册、已验收候选的 help 捕获和使用文档。示例面向候选版本；当前全局安装尚未更新。本次仅补报告，未执行示例中的创建、转换、删除或发布。

旧入口保留，但不是新模型的别名。
mf article 仍服务 legacy 内容；项目级 Article 命令拒绝新布局。新建 mind／output 不会自动导入旧文章，category ↔ bundle 转换也不是 legacy 文章迁移。
操作改动前当前候选行为变化
创建项目
mf project new research
mf project new research --layout category
mf project new research --layout bundle
新增 --layout；二选一，在新建时指定。现有项目不能靠这个参数或直接改配置来转换。
创建内容
mf article new "方案" --slug design --file -p research
mf mind new brief -p research
mf output new brief design --file -p research
旧文章入口 → mind 与 output 分别创建。--file 仍表示单文件；省略时创建分块 output。
查询与索引
mf article list / show / index
mf mind list / show / index
mf output list / show / index
此行斜线是子命令枚举。mind 可无 output；索引投影不把 output 登记为独立 mind。
改名／移动／删除
mf article rename / move / remove
mf lifecycle mind-rename / mind-move / mind-remove
mf lifecycle output-rename / output-move / output-remove
按对象粒度选择；默认维护受管引用。删除有入站引用时拒绝。不是把 article 替换成 mind 就能得到全部命令。
资源扩展
本轮前无 additional 专用命令组
mf additional list / show / rename / remove
新增动态资源管理；rename 目标是具体项目相对路径，不是全项目类别改名。
构建
mf build <ARTICLE> --out <OUTPUT>
mf build projects/research::brief::design --format html
原入口扩展到 output；默认仍为 Markdown。--out 是目标路径，必须遵守 build 根及源稿保护。
发布与记录更新
mf publish run <ARTICLE>
mf publish update <ARTICLE> --target <TARGET>
mf publish run projects/research::brief::design --target local-test
mf publish update projects/research::brief::design --target local-test --set status=published
命令组沿用，选择器支持完整 output identity。target 须已配置，发布不会自动 build；F16 目录正文定位修复保留。

表中的 / 表示可选子命令列表，不是可以直接复制执行的语法；下面给出完整命令示例。

四组新增命令，一张操作地图

mind · 管内容集合

零 output 的 mind 也可以存在。

mf mind new / list / show / index

output · 管可编辑源稿

每份 output 归属一个 mind，支持单文件或分块。

mf output new / list / show / index

lifecycle · 管变更与恢复

转换布局、改名、移动、删除以及中断事务恢复。

convert
mind-rename / mind-move / mind-remove
output-rename / output-move / output-remove
apply / status / resume / rollback

additional · 管扩展资料

识别与管理具体文件／目录，不自动构建或执行。

mf additional list / show / rename / remove

可以照着理解的一条新流程

在已初始化的 mf 仓库中，新建项目、mind 和两份 output；编辑生成的源稿后再构建。以下采用分类布局，换成 --layout bundle 即选择聚合布局。

mf project new research --layout category
mf mind new brief -p research
mf output new brief design -p research
mf output new brief summary --file -p research
mf output list projects/research::brief

# 编辑生成的源稿后，显式选择要构建的 output
mf build projects/research::brief::design
mf build projects/research::brief::summary --format html --output json

三个容易混淆的参数

  • --format markdown|html：构建文件的格式，默认 Markdown。
  • --output text|json 或 --json：CLI 响应格式，不决定文件格式。
  • --out <PATH>：构建文件保存位置，新 output 须在项目 build/ 内。

选择器需要包含归属

mind：projects/research::brief
output：projects/research::brief::summary

完整 identity 自带项目，不必再加 -p。零 output 不能 build；多个 output 要显式选择或配置 default_output，歧义不会取第一个。

布局转换、只读检查与扩展资源

先预演，明确执行后再转换

mf lifecycle convert --to bundle -p research --dry-run
mf lifecycle convert --to bundle -p research --yes

# 转回 category 也走同一入口
mf lifecycle convert --to category -p research --dry-run

# 改 mind 名与改 output 名是两种操作
mf lifecycle mind-rename projects/research::brief renamed --dry-run
mf lifecycle output-rename projects/research::brief::summary short --dry-run

--dry-run 不落盘；执行用 --yes。已有 Lance 权威后端时转换明确拒绝，不静默降级。status／resume／rollback 针对事务；rollback 不是任意已完成转换的撤销按钮。

mf lifecycle status
mf lifecycle resume
mf lifecycle rollback

检查投影，管理具体 additional

mf mind index --check -p research --json
mf output index --check -p research --json

# 仅在需要重建派生投影时执行
mf mind index -p research

mf additional list projects/research::brief
mf additional show reviews/brief.md -p research
mf additional rename reviews/brief.md assessments/brief.md -p research --dry-run
mf additional remove assessments/brief.md -p research --dry-run

additional 示例假定 category 项目中已有对应资源；remove 示例以 rename 已执行为前提。bundle 对应路径为 brief/reviews.md 与 brief/assessments.md。--check 只读：一致退出 0，发现差异退出 1；index 只重建投影，不自动修复权威绑定。

没有新增 mf feedback，也没有 mf mind rename 或 mf output rename 入口；改名使用上面明确列出的 lifecycle 子命令。

05 / BOUNDARIES

已完成什么，尚未做什么

已确认的范围取舍

  • 不要求旧客户端兼容；支持两种布局的显式双向转换。
  • 共享资料归属一个 mind，其他 mind 引用；不增加项目共享资料层。
  • 没有 Feedback 状态 CLI，也没有统一反馈清零发布门槛。
  • HTML 允许固定版本 Mermaid CDN；不包含离线打包、公式、脚注或插件套件。
  • 短文单文件本来已有能力，改进的是流程选择；撤回的中文 block 文件名不重启。

验证限制与保留记录

  • Lance 权威布局转换明确拒绝，已验证零写入；不宣称该迁移成功路径已支持。
  • RAG 使用关键词降级检索，未配置 embedding，不宣称语义向量召回已验证。
  • 2 项 term lint 规则／严重性测试仍 ignored；既有帮助快照尾空格仍记录为 diff 检查提示。
  • 未迁移真实 minds／logbooks 内容；发布验证仅使用合成 fixture 的本地目标。
  • 本机已通过局域网地址读取页面，尚无第二台物理设备的联网实测。
