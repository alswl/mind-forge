本稿为 2026-10-25 的规划初筛，未执行缺陷复现或功能实现。目标原文与任务顺序以[Logbook](#private-source-provenance)为准。建议覆盖 2026-09-13 至 2026-10-25 的反馈及当前未关闭事项；旧归档仅作去重依据，不将过去修复重新算作需求。

## 判定方法

先还原“谁在什么场景遇到什么问题”，再判断反馈指定的实现是否必要。每项分开记录性质（需求、bug、假需求候选、待核）、责任（CLI、上游技能、宿主流程）、处置（采纳、替代、延后、不采纳建议）与证据强度。性质与优先级独立。

- 需求：有真实未满足的结果，现有契约没有承诺；不能把指定命令名当成需求本身。
- bug：实际行为违反现有承诺或一致性约束；需要基线版本、最小输入、命令、退出码、前后状态及预期。反馈原文是线索，源码吻合是支持，运行复现才补齐行为证据。
- 假需求候选：问题前提不成立、现有能力已满足、已撤回，或所提机制无法产生声称的结果。说明反证和替代路径；需求成本高、发生少或暂缺证据不等于假需求。
- 待核：基线、场景、责任或证据缺失。保留未知，不强行三选一。同一反馈可拆出 bug 与增强需求。

## 基线与核验边界

本机 mf 为 0.4.2-dev+23b047c；业务仓 HEAD 为 23b047c65151de670098a197c89612b88d594cad，未 fetch，不声称上游最新。本设计位于该仓隔离 worktree；共享主树未改动。

只读依据：`mf article rename --help` 无 --update-references；`src/service/article/rename.rs` 118–176 行处理 Prompt/Thinking 并刷新投影，但这是串行操作，不能据此称为完整事务。`src/service/publish.rs` 的 run 使用 resolve_article；update 85–117 行拒绝斜线、只匹配 markdown 单文件。这支持 F01/F16 的拆分判断，未代替复现。

后续获准核验在隔离 worktree 使用合成 fixture，覆盖 single-file 与 directory article、Prompt/Thinking、发布记录、内部引用。真实 minds/logbooks 内容只读；不运行真实发布、迁移或 source sync。复现缺陷要比较 stdout/stderr/退出码及文件前后状态；已解决项记录适用版本，未复现项明确差异。此处是验证设计，不是已通过证据。

## 方案与取舍

建议先核验旧稿发布、定位与绑定一致性问题，再补提示和诊断体验；大布局需求单独出设计。优先级仍为提案，以数据损坏/陈旧输出风险、影响面和复现证据为据，不按反馈标题排序。

按 mind 聚合保持项目级配置、既有分类布局兼容，以及 Article/Prompt/Thinking/Source 职责分离。用户已确认同时支持按类型分类与按 mind 聚合两种物理布局，由项目选择；不再以仅改变导航替代聚合目录。任何方案都避免一份内容维护两份副本，迁移需预演冲突、引用变化与回滚边界，布局和 single doc 选择正交。

最终优化方案每项包括用户结果、责任仓、现有替代、采纳建议、变更范围、兼容性风险、验收用例与未决问题。只在 Logbook 维护执行顺序，本稿不另列开发待办。

## 设计交付范围与验证安排

2026-10-25 用户要求把设计列为独立 Stage，正式交付在 Logbook Stage 02。该阶段需形成以下契约，当前仅确定交付范围，具体命名与接口留待设计，不伪装成已确认决定。

| 设计对象 | 必须说清 | 验收依据 |
| --- | --- | --- |
| 项目布局 | 类型分类与 mind 聚合的目录实例、配置项、缺省行为、同仓异构项目；单文件/分块保持正交 | 现有项目零配置不变，新项目可显式选择；四种组合可定位 |
| 关联与迁移 | Article/Prompt/Thinking/Source/Asset、共享资料及发布记录映射；引用范围、冲突、失败与恢复边界 | 双向合成迁移、预演零写入、重复执行、失败恢复及引用完整性 |
| CLI/Skill 分工 | 逐项标记已支持、需补缺或保留语义判断；确认最小命令面和结构化错误 | CLI 用例检验确定性不变量，Skill 不自行重写 CLI 所属状态 |
| 行为评测 | 真实输入、期望行为、评分依据、运行证据、候选版本及基线比较条件 | 正例完成授权动作，反例保留未知和未决反馈；失败不宣称成功 |

双布局的正反例采用中性合成内容，不复制两仓真实业务正文到上游测试。迁移验证覆盖共享资料仍可复用、旧布局继续工作、私有内容不进入公开产物；发布验收使用本地目标，不触发远端发布。

先在单个 CLI 候选上固定行为，再评测 Skill 调用该候选的实际表现。保持旧有 7 个反馈/建议用例，按本轮行为增补短文形态、两布局绑定、旧稿与新材料合并、部分完成、已有授权、失败处理与下沉调用场景。场景可复用夹具，不用机械笛卡尔积放大模型运行次数。性能和触发评测本轮不另设目标；若发现相关回归，保留事实并判断是否影响已有验收。

总体交付为候选代码、设计与使用文档、CLI 回归及真实 Skill evals 结果、未结事项和可读审阅入口。任务顺序仅在 Logbook 维护；尚未授权制品发布、远端 PR 或真实内容迁移，不预设这些作为完成条件。
